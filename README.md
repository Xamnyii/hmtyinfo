## Deploy on Vultr

The project can run entirely on one Ubuntu 24.04 Vultr VPS: MongoDB listens only on `127.0.0.1:27017`, PM2 runs Next.js on `127.0.0.1:3000`, and Nginx serves the public HTTPS site on ports `80` and `443`.

### Before provisioning

1. Create an Ubuntu 24.04 VPS on Vultr and point an `A` record for your domain to its public IPv4 address.
2. Open TCP ports `22`, `80`, and `443` in the Vultr firewall. Do not expose port `27017`.
3. Ensure the VPS can clone your repository. For a private GitHub repository, add an SSH deploy key to the server before running the script.
4. SSH to the server as root and run the following from a clone of this repository:

```bash
chmod +x deploy/vultr-install.sh
sudo ./deploy/vultr-install.sh git@github.com:Xamnyii/hmtyinfo.git rmrd.tech
```

The installer sets an autogenerated MongoDB password in `/var/www/hmtyinfo/.env.production` with owner-only permissions, creates a database user limited to `hmtyauth`, enables MongoDB authentication, starts the app with PM2, configures Nginx, and obtains a Let's Encrypt certificate with Certbot.

`MCP_SERVER_URL` is required only for the MCP API routes. When the MCP server is on the same VPS, set it to its local URL in `/var/www/hmtyinfo/.env.production`, then run:

```bash
sudo -u hmty pm2 restart hmtyinfo --update-env
```

### Updating the application

```bash
sudo -u hmty bash -lc 'cd /var/www/hmtyinfo && git pull && npm ci && npm run build && pm2 reload hmtyinfo --update-env'
```

Check the services after provisioning or an update:

```bash
systemctl status mongod nginx
sudo -u hmty pm2 status
curl -I https://rmrd.tech
```

The tracked [.env.production.example](.env.production.example) documents the available environment variables. Never commit the real `.env.production` file.
